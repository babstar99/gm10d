# gm10d v0.1.3 – First public release

First public release of **gm10d**, a lightweight Linux daemon for the
Black Cat Systems GM-10 serial radiation detector.

gm10d is a modern replacement for the acquisition functionality of
gm4lin, designed for unattended monitoring on current Linux systems.

It reads individual GM-10 particle events over RS-232, calculates
radiation count rates, publishes measurements through MQTT for Home
Assistant, and exposes Prometheus-compatible metrics for systems such as
VictoriaMetrics and Grafana.

## Highlights

- Native Linux serial support using POSIX `termios`
- Supports motherboard RS-232 ports and USB-to-RS232 adapters
- GM-10 hardware operation based on the original gm4lin 1.2.15 source
- 57600 baud, 8N1 operation
- DTR control for GM-10 detector power
- One received serial byte counted as one particle event
- Rolling 60-second CPM
- CPS measurement
- 10-second count and gm4lin-compatible extrapolated CPM
- Cumulative particle counter
- MQTT publishing using libmosquitto
- Home Assistant MQTT discovery
- MQTT online/offline availability reporting
- Prometheus-compatible `/metrics` HTTP endpoint
- Automatic serial reconnect handling
- systemd service support
- GPL-2.0-or-later

## Home Assistant

Home Assistant MQTT discovery automatically creates a
**Black Cat Systems GM-10** device containing:

- Radiation CPM
- Radiation CPS
- Radiation Pulses

No Home Assistant YAML configuration is required when MQTT discovery is
available.

## Tested hardware

### Native serial

Validated using a Linux 16550A UART exposed as:

```text
/dev/ttyS0
```

Long-duration testing showed stable acquisition with zero serial read
errors and zero reconnects.

### USB-to-RS232

Validated with:

**StarTech ICUSB2321F**

- FTDI FT232R chipset
- Linux `ftdi_sio` driver
- Persistent `/dev/serial/by-id/...` device path
- DTR power control confirmed
- Count rate consistent with the native UART baseline
- Zero serial read errors or reconnects during validation

Using `/dev/serial/by-id/...` is recommended instead of `/dev/ttyUSB0`
for permanent installations.

## v0.1.3 fix

v0.1.3 fixes an HTTP timing race discovered during VictoriaMetrics
vmagent testing.

Earlier versions could accept a TCP connection before the HTTP request
data had arrived and close the connection prematurely, resulting in
occasional:

```text
connection reset by peer
```

errors during Prometheus scraping.

The metrics server now waits for the HTTP request headers before
responding.

This has been validated with VictoriaMetrics vmagent scraping gm10d
every 15 seconds.

## Dependencies

Runtime requirements are deliberately minimal:

- standard Linux/POSIX C runtime
- libmosquitto

No Python, pip, virtual environments, containers, or language-specific
package ecosystem is required.

On Debian:

```bash
sudo apt install libmosquitto1
```

For building:

```bash
sudo apt install build-essential libmosquitto-dev
```

## Building

```bash
make
make check
```

```bash
make check WERROR=1
```
